# SQL Server Backup Tool

A Windows desktop app (C# / .NET 10 / WinForms) for backing up and restoring SQL Server databases. See [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md).

## Features
- **Several servers**: pick a server from the drop-down; add, edit and remove servers in **Settings**.
- **Backup**: tick databases, then **Back up selected**. Options: copy-only, compression, checksum, verify after backup. Progress is shown per database, and you can cancel.
- **Backup history**: click a database to see its last 50 backups (read from `msdb`).
- **Restore**: double-click a full backup in the history (or use **Restore from file...**). You can restore over the original database (you're asked to confirm the overwrite) or **as a copy under a new name**. For a copy, the data and log files are given new names automatically so the original database is never touched.
- **Retention**: after each successful backup the tool can delete its own old backups: keep the newest *N*, and delete the rest once they are older than *D* days. Only backups made by this tool are deleted, and the newest is always kept.
- **Encrypted connection strings**: in Settings → Edit server, tick *Encrypt*. The string is stored as `dpapi:user:…`, which only you can read on this PC. Choose *machine* scope instead if a scheduled task runs under a different Windows account.
- **Command line and scheduling**: **Copy command line** gives you the exact command for the current selection. **Schedule...** creates a daily or weekly Windows Task Scheduler task.

## Configuration: `appsettings.json` (next to the exe)
| Key | Meaning |
|-----|---------|
| `Servers[].Name` / `ConnectionString` / `BackupFolder` | One entry per SQL Server. The connection string can be plain text or `dpapi:...` encrypted. `BackupFolder` overrides the default folder for that server. |
| `DefaultServer` | Server selected when the app starts |
| `Backup.DefaultFolder` | Folder **on the SQL Server machine**. Leave it empty to use the server's own default backup folder. |
| `Backup.FileNamePattern` / `TimestampFormat` | e.g. `{database}_{timestamp}.bak` / `yyyyMMdd_HHmmss` |
| `Backup.CopyOnly/Compression/Checksum/Verify` | Default values for the option checkboxes |
| `Backup.IncludeSystemDatabases` | Also list master, model and msdb |
| `Backup.Retention.Enabled/KeepLast/OlderThanDays` | Retention rule; `Enabled` is the checkbox default |

The old v1 format (`ConnectionStrings:SqlServer`) is still accepted and converted to the new format automatically.

## Command line
```
SqlBackupTool.exe --backup --server Local --dbs Sales,HR [--folder D:\Backups] [--no-verify] [--retention]
SqlBackupTool.exe --backup --all
SqlBackupTool.exe --list [--server NAME]
SqlBackupTool.exe --protect-config [--machine]     # encrypt every plain connection string in appsettings.json
SqlBackupTool.exe --help
```
Exit codes: `0` all OK, `1` a backup failed or a database was skipped, `2` invalid arguments or config, `3` cannot connect.
Output goes to the console and to `logs\backup_yyyyMMdd.log`. In PowerShell, use `Start-Process ... -Wait -PassThru` to read the exit code, because the exe is a GUI app.

## Build / run / test
```
dotnet build SqlBackupTool.sln
dotnet run --project src/SqlBackupTool.App
dotnet publish src/SqlBackupTool.App -c Release -r win-x64 --self-contained false -o publish

dotnet test tests/SqlBackupTool.Tests
$env:SQLBACKUP_TEST_CS="Server=localhost;Integrated Security=True;TrustServerCertificate=True;"
dotnet test tests/SqlBackupTool.Tests    # also runs the end-to-end test (temporary databases only)
```
The icon is generated by `tools/make-icon.ps1`.

## Permissions
- Backup: `db_backupoperator` on each database (or `sysadmin`), plus read access to `msdb` for the history.
- Restore: `dbcreator` (new database) or `sysadmin` / `db_owner` (overwrite an existing one).
- Retention on a **remote** server: `sysadmin` (it uses `xp_delete_file`). On a local server the files are deleted directly.
- The SQL Server **service account** must be able to write to the backup folder.
